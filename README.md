# 夏の勉強ガチャ 🎰

塾の夏期講習イベント用のガチャシステム。生徒が貯めた「スイカポイント」を使って回すガチャを、ブラウザ上で再現します。

## できること

### 生徒画面
- 3種類のガチャから選んで回す
  - 🎁 **ノーマルガチャ** — 気軽に回せる定番
  - ✨ **プレミアムガチャ** — ちょっといい景品
  - 🌟 **日替わりガチャ** — 本日限定ラインナップ
- カプセル機がぷにっと揺れる演出 → ドロップ＆バウンドアニメ → コンフェッティで結果発表
- レアリティ別の演出（SSRはキラキラ光る）
- 「景品を見る」で各ガチャのラインナップと当選確率を確認

### 管理画面（`/admin`）
- 景品の追加・編集・削除（絵文字・名前・説明・レアリティ・重み・在庫）
- ガチャ自体の設定変更（名前・アイコン・テーマカラー・説明）
- 在庫のリセット
- 当選履歴の集計と表示
- 履歴のリセット

## セットアップ

### 必要なもの
- Node.js 22 以上（`node:sqlite` を使うため）
- npm

### インストール

```bash
cd gachya
npm install
cd server && npm install
cd ../client && npm install
```

または一発で：

```bash
npm run install:all
```

## 起動

```bash
npm run dev
```

- 生徒画面: <http://localhost:5173>
- 管理画面: <http://localhost:5173/admin>
- API: <http://localhost:3001>

開発サーバー(Vite)と APIサーバー(Express)が同時に起動します。

個別に起動する場合：
```bash
npm run dev:server   # API のみ
npm run dev:client   # フロント のみ
```

## 運用（本番）: 職員PCでサーバー起動 ＋ ガチャ用PCで生徒がプレイ

2台構成で、役割を分けます。

- **職員PC** … サーバーを起動する。**管理画面（景品・在庫）はこのPCだけ**で開ける
- **ガチャ用PC** … 生徒が順番にガチャを回す。**ガチャしかできない**（管理画面はブロックされる）

管理画面（`/admin` と `/api/admin/*`）は、サーバーを動かしているPC＝職員PC（localhost）からのアクセスのみ許可します。ガチャ用PCはLAN経由の別PC扱いになるため、`/admin` を開こうとしてもトップへ戻され、管理APIは 403 になります（`server/index.js` の `isLocalRequest`）。生徒が誤って管理画面に入る心配はありません。

### かんたん起動（スタッフ向け・両方ダブルクリックだけ）

- **職員PC**: `ガチャ起動.bat` をダブルクリック → サーバーが起動し、管理画面（`http://localhost:3001/admin`）が自動で開く。落ちても自動再起動
- **ガチャ用PC**: `ガチャ画面を開く.bat` をダブルクリック → 職員PCのサーバーを自動で見つけて、Edgeのキオスクモード（アドレスバー無しの全画面）でガチャ画面が開く。終了は `Alt+F4`

初回のみ、`ガチャ画面を開く.bat` の `SERVER=` に職員PCのコンピューター名（職員PCで `hostname` で確認）を書いておく。名前はIPと違って変わらないので、以降は毎日ダブルクリックだけでよい。名前で繋がらないネットワークの場合はIPアドレスを書く（この場合は朝に変わっていないか注意）。

Mac確認用に `ガチャ起動.command`（職員PC側と同じ動き）もある。詳しい運用は `スタッフ手順書.txt` を参照。

### コマンドで起動する場合

```bash
npm start   # client をビルドして server が dist/ ごと配信（port 3001）
```

- ガチャ用PCから: `http://<職員PCのIP>:3001`
- 管理画面（職員PCのみ）: `http://localhost:3001/admin`

※ 職員PCとガチャ用PCは同じWi-Fi（塾内ネットワーク）に接続する。ガチャ用PCから繋がらない場合は、職員PCのファイアウォールでNode.jsの受信接続を許可する。IPは Windows は `ipconfig`、Mac は `ipconfig getifaddr en0` で確認（毎朝変わることがある）。管理画面は必ず `localhost` で開くこと（職員PCで自分のIP経由で開くとブロックされる）。

## 技術スタック

| レイヤー | 技術 |
|---|---|
| フロントエンド | React 18 + Vite + React Router |
| バックエンド | Node.js + Express |
| データベース | SQLite（Node.js組み込み `node:sqlite`） |
| スタイル | プレーンCSS（ツムツム風の丸み・パステル・ぷにっと弾むアニメ） |

ネイティブビルドが必要なパッケージは使っていません。`npm install` でビルドエラーが起きにくい構成です。

## データ

`server/gacha.db` に SQLite ファイルとして保存されます。初回起動時に3つのガチャと初期景品が自動投入されます。

### 初期データを差し替えたい場合
1. `server/gacha.db` を削除
2. `server/db.js` の `insertPrize.run(...)` 群を編集
3. サーバー再起動

### バックアップ
`server/gacha.db`（および `gacha.db-wal`, `gacha.db-shm` があれば）をコピーすればOK。

## カスタマイズのヒント

| やりたいこと | どこを触る |
|---|---|
| 景品の追加・修正 | 管理画面（ブラウザ）から |
| 当選確率の調整 | 管理画面で各景品の「重み」を変更（合計の比率で決まる） |
| 在庫管理 | 管理画面で「初期在庫」を設定。-1 で無制限 |
| ガチャの名前・色 | 管理画面の「ガチャ設定」ボタンから |
| 演出のスピード | `client/src/pages/Gacha.jsx` の `setTimeout(r, 2600)` と `client/src/styles.css` の `@keyframes dropBounce` を同時に変更 |

## 注意

- **認証はありません**。管理画面 `/admin` も誰でも開けるので、塾内ネットワークや短期イベント前提です。インターネットに公開するなら Basic 認証等を追加してください。
- **ポイント管理は含まれていません**。ガチャは無条件で回せます（ポイント消費はスタッフが別途管理する想定）。
