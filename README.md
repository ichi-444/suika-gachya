# 夏の勉強ガチャ 🍉

塾の夏期講習イベント用のガチャシステム。生徒が頑張って貯めた **スイカポイント** を消費して、ブラウザ上でガチャを回します。テーマは「スイカ × 夏」。

生徒はキオスク（ガチャ用PC）で自分の名前を選んでガチャを回し、スタッフは管理画面から景品・確率・在庫、そして生徒ごとのスイカポイント残高を調整します。

## できること

### 生徒画面（キオスク）
- トップで **自分の名前を選ぶ** → ヘッダーに **スイカポイント残高** が表示される（「べつのひと」でリセット）
- 3種類のガチャを、それぞれの **コスト（消費ポイント）** を払って回す
  - 🖊️ **文房具ガチャ** — 可愛い文房具が当たるよ！（25pt）
  - 🍩 **食べ物ガチャ** — おかしやアイスが当たるよ！（25pt）
  - 🌟 **プチガチャ** — 5ポイントでミニ景品ゲット！（5pt）
  - ※ガチャ名・アイコン・コストは管理画面から変更でき、上記は初期設定です
  - ※残高が足りないと回せません
- **スイカ割り演出** — 大きなスイカと棒が登場 → タップで割れて景品が飛び出す
- 🟡 **金色スイカ（SR以上確定）** — 一定確率（既定8%）で出現し、SR/SSR だけの抽選になる
- 「景品を見る」で各ガチャのラインナップと **当選確率** を確認
- 「獲得景品」（`/wins`）で **いつ何を当てたか** を新しい順に確認。景品を渡したら **受け取り済みバッジ** が付く

### 管理画面（`/admin`・職員PCのみ）
- 景品の追加・編集・削除（絵文字・名前・説明・レアリティ・重み・在庫）
- ガチャ設定の変更（名前・アイコン・テーマカラー・説明・**コスト**）
- **生徒とスイカポイント** の管理（生徒の追加、頑張りに応じたポイントの付与／減算）
- **ガチャ履歴**（だれが・いつ・何を当てたか）と、景品の **引き渡しチェック**
- **景品ごとの集計**
- 在庫のリセット／履歴のリセット

## スイカポイントの仕組み

- 生徒ごとに残高（スイカポイント）を持ちます。スタッフが頑張りに応じて管理画面で付与します。
- ガチャは1回ごとに **コスト** を消費します（ガチャごとに設定。初期値は 文房具ガチャ=25 / 食べ物ガチャ=25 / プチガチャ=5）。
- 残高が足りなければガチャは回せません。
- 生徒の識別は「名前をタップするだけ」（PIN等の本人確認はなし＝短期イベント前提）。

## セットアップ

### 必要なもの
- Node.js 22 以上（データベースに組み込みの `node:sqlite` を使うため。新しめのバージョン推奨）
- npm

### インストール

```bash
npm run install:all
```

（ルート・`server`・`client` の依存をまとめて入れます。ネイティブビルドが必要なパッケージは使っていないので、ビルドエラーが起きにくい構成です。）

## 起動（開発）

```bash
npm run dev
```

- 生徒画面: <http://localhost:5173>
- 獲得景品: <http://localhost:5173/wins>
- 管理画面: <http://localhost:5173/admin>
- API: <http://localhost:3001>

開発サーバー(Vite)と APIサーバー(Express)が同時に起動します。個別に起動する場合：

```bash
npm run dev:server   # API のみ
npm run dev:client   # フロント のみ
```

## 運用（本番）: 職員PCでサーバー起動 ＋ ガチャ用PCで生徒がプレイ

2台構成で、役割を分けます。

- **職員PC** … サーバーを起動する。**管理画面（景品・在庫・生徒・ポイント）はこのPCだけ**で開ける
- **ガチャ用PC** … 生徒が順番にガチャを回す。**ガチャしかできない**（管理画面はブロックされる）

管理画面（`/admin` と `/api/admin/*`）は、サーバーを動かしているPC＝職員PC（localhost）からのアクセスのみ許可します。ガチャ用PCはLAN経由の別PC扱いになるため、`/admin` を開こうとしてもトップへ戻され、管理APIは 403 になります（`server/index.js` の `isLocalRequest`）。生徒が誤って管理画面に入る心配はありません。

### かんたん起動（スタッフ向け・ダブルクリックだけ）

- **職員PC**: `ガチャ起動.bat` をダブルクリック → サーバーが起動し、管理画面（`http://localhost:3001/admin`）が自動で開く。落ちても自動再起動
- **ガチャ用PC**: `ガチャ画面を開く.bat` をダブルクリック → 職員PCのサーバーを自動で見つけて、Edgeのキオスクモード（アドレスバー無しの全画面）でガチャ画面が開く。終了は `Alt+F4`

初回のみ、`ガチャ画面を開く.bat` の `SERVER=` に職員PCのコンピューター名（職員PCで `hostname` で確認）を書いておく。名前はIPと違って変わらないので、以降は毎日ダブルクリックだけでよい。名前で繋がらないネットワークの場合はIPアドレスを書く（この場合は朝に変わっていないか注意）。

Mac確認用に `ガチャ起動.command`（職員PC側と同じ動き）もある。詳しい運用は `スタッフ手順書.txt` を参照。

### コマンドで起動する場合

```bash
npm start   # client をビルドして server が dist/ ごと配信（port 3001）
```

- ガチャ用PCから: `http://<職員PCのIP>:3001`
- 管理画面（職員PCのみ）: `http://localhost:3001/admin`

※ 職員PCとガチャ用PCは同じWi-Fi（塾内ネットワーク）に接続する。ガチャ用PCから繋がらない場合は、職員PCのファイアウォールでNode.jsの受信接続を許可する。IPは Windows は `ipconfig`、Mac は `ipconfig getifaddr en0` で確認（毎朝変わることがある）。管理画面は必ず `localhost` で開くこと（職員PCで自分のIP経由で開くとブロックされる）。

## 技術スタック

| レイヤー | 技術 |
|---|---|
| フロントエンド | React 18 + Vite + React Router |
| バックエンド | Node.js + Express |
| データベース | SQLite（Node.js組み込み `node:sqlite`） |
| スタイル | プレーンCSS（スイカ配色・レトロなガチャポン機・bobble/wobbleアニメ・スイカ割り演出） |

## データ

`server/gacha.db` に SQLite ファイルとして保存されます（`gachas` / `prizes` / `pulls` / `students` の4テーブル）。初回起動時に3つのガチャと初期景品、サンプル生徒が自動投入されます。

- **マイグレーション対応**: 起動時に列やテーブルの有無を確認し、足りなければ自動で追加します（既存の `gacha.db` を消さずにポイント経済へ移行できる）。
- **初期データを差し替えたい場合**: `server/gacha.db` を削除 → `server/db.js` の `insertPrize.run(...)` 群を編集 → サーバー再起動。
- **バックアップ**: `server/gacha.db`（および `gacha.db-wal`, `gacha.db-shm` があれば）をコピーすればOK。

## カスタマイズのヒント

| やりたいこと | どこを触る |
|---|---|
| 景品の追加・修正 | 管理画面（ブラウザ）から |
| 当選確率の調整 | 管理画面で各景品の「重み」を変更（合計の比率で決まる） |
| 在庫管理 | 管理画面で「初期在庫」を設定。-1 で無制限 |
| ガチャの名前・色・コスト | 管理画面の「ガチャ設定」ボタンから |
| 金色スイカ（SR確定）の確率 | `server/index.js` の `GOLDEN_CHANCE`（既定 `0.08` = 8%） |
| スイカ割り演出のスピード | `client/src/pages/Gacha.jsx` の `BREAK_MS`（既定1500ms）と `client/src/styles.css` の「スイカ割り」節（`stickSwing`/`halfLeft`/`halfRight`/`prizeOut`）を合わせて変更 |
| レアリティ | 現状 N / R / SR / SSR の4段階。増やすなら `Prizes.jsx` / `Admin.jsx` / `styles.css` を合わせて変更 |

## 注意

- **認証はありません**。管理画面 `/admin` は「サーバーを動かしている職員PC（localhost）からのみ開ける」という仕組みで生徒の誤操作を防いでいますが、パスワード認証ではありません。インターネットに公開するなら Basic 認証等を追加してください。
- **本人確認はありません**。生徒は名前をタップするだけなので、別人の名前を選べてしまう点は短期イベント前提の割り切りです。
- 「日替わりガチャ」は自動切替ではなく、スタッフが管理画面でその日の景品を有効／無効にする運用です。
